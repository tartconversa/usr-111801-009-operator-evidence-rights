# 景区资料协作台账：运营方更替时的材料使用权

服务登记资料来源、字段、原件、使用许可、数据产品与交付凭据，并记录景区运营关系沿革与经营权接手。示例主体和记录均为虚构，不连接真实文旅部门。

需要 Python 3.10 或更新版本，不依赖第三方包。

运行项目测试：python -m unittest discover -s tests -v。
检查源码：python -m compileall -q exchange。
运行本地演练：python -m exchange --database demo.db。

## 模块分工

- catalog.py 登记来源字段和原件；`open_asset` 是取原件正文的唯一关口，先过许可校验再放行。
- tenure.py 登记景区（sites）与运营方任期（tenures），提供在任运营方查询与沿革清单。
- handovers.py 登记经营权接手回执；回执只证明运营关系交接，本身不授予任何材料使用权。
- grants.py 管理使用许可：支持来源级许可与按原件版本限定的补签许可，支持撤销；每次判断实时生效。
- policy.py 管理辖区/分类/用途策略，带修订号。
- gate.py 统一校验关口：来源状态、版本级许可、策略三方交叉判断，供取件、交付和清单共用。
- availability.py 面向新团队的可见性清单与复核引用校验：看得到来源与指纹，但未授权版本标记为暂不可用，且不返回正文。
- products.py 编排复核材料（可挂景区，跨景区引用被拒），delivery.py 出具回执并快照当时运营方与每条引用的许可依据，audit.py 记录操作。

## 关键边界

1. 经营权接手不自动移交材料使用权：旧运营方的许可不随回执转移，新团队默认只看到“有来源但暂不可用”的材料。
2. 补签许可可限定到具体原件版本，只有范围内版本放行，同来源其他版本仍不可用。
3. 交付回执是历史凭据，快照交付时点的在任运营方和许可编号；此后经营权变更、许可撤销都不改写旧回执。
4. 许可在移交中途被撤销时，即使接手回执和交付回执都已生成，再次取件或新交付仍被实时拒绝，拒绝原因写入审计。
